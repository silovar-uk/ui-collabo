## Phase 2(見て選ぶ)

- ラダーの相対チップは5.6.1の語彙(ずっと小さく/少し小さく/少し大きく/ずっと大きく)をそのまま出力に使う。5.8の例文にあった「今より1段小さく」という言い回しは、5.6.1のチップ仕様が確定する前の初期メモと判断し採用しなかった(Phase2受け入れ基準の文言「文字を少し小さく」が5.6.1側の語彙と一致することからも裏付け)
- 「＋ こうしたい」の分類は5.4の「位置・大きさ/色/文字/余白/形/動き/ルールに合わせる/ひとこと」を字義通りには分けず、実装上は「色/文字の雰囲気/量(ラダー、8属性から選択)/動き/ルールに合わせる/ひとこと」の6分類にまとめた。余白・形(角丸・線の太さ)・全体の大きさはいずれもラダー8属性の一部であり、量として一箇所にまとめる方が「選択肢は実物で見せる」原則にも合うと判断
- 色ノートは1箇所に複数付けられる(役割違い、例: 文字色と背景色を両方指定)。文字の雰囲気・動きは1箇所につき1つのみ(仕様の想定に合わせる)
- 動きのプレビューはクリック/ホバーで再生されるが、強さ(intensity)は視覚的な差までは作り込まず、出力テキストにのみ反映する(ponytail: 5段階の見た目差の作り込みは省略、必要になれば強度に応じた移動量・不透明度の変化を追加)
- 「ルールに合わせる」は `docs/DECISIONS.md` の`ruleRefOptions`が返す項目がある場合のみ表示する。Phase3で「ルールにする」ボタンが実装されるまでは常に非表示になる想定
- 参考画像(imageRole=reference)モードの色ノートは、スポイトで拾った値をそのまま target に入れ、出力は「参考画像①の色 #hex を強調色に」の形にする(仕様5.8の例文どおり。role未指定時は「強調」を既定にした)
- 位置・大きさの差分(targetRectとrectの比較)は imageRole==='draft' のときだけ出力する。draftで箇所を作ったあとにimageRoleをreferenceへ切り替えても、古いtargetRectの差分が紛れ込まないようにするため

## Phase 3(蓄積)

- 色ノートの役割(5.6.2: 文字/背景/強調/線)とルールのパレット役割(6章のスキーマ: bg/text/accent/sub)は仕様上も語彙が異なる。「ルールにする」で昇格するとき、線(line)は最も近い補助(sub)に対応させた

## UI改善(PLAN-UI.md フェーズA〜E)

- LivePreview(`src/panels/LivePreview.tsx`)の高さ制限は、PLAN-UI.md 記載の `max-height: 40%` ではなく `40vh` を採用した。`.side-panel` の2段グリッドは行が `auto` サイズのため、子要素へのパーセント指定の基準が定まらず機能しない。ビューポート高基準の `vh` なら常に確定値になり、意図(画面の4割程度に収める)も達成できる
- `.live-preview` に `overflow: hidden` を追加し、`.live-preview-body` に `flex: 1; min-height: 0;` を追加した。付けないと `display:flex` 内の `overflow:auto` 子要素が内容の実サイズまで伸び、ページ全体が縦スクロールしてしまう(flexboxの既知の挙動)。ブラウザ実機確認で発見して修正した
- フェーズB-3の「`.app-shell.is-drag-over` の見せ方を強くする」は、実装上はApp側の `dragOver` ステートを `Empty` へpropとして渡し、`.empty-dropzone.is-drag-over` に直接スタイルを当てる形にした。ドロップ処理自体は既存どおりApp最上位の1箇所に残し、二重登録によるファイル二重取り込みを避けている
- C-3「このボードの基準にする」の`<details>`初期開閉は、対象ノート種別ごとの既存ルール有無ではなく、ボード全体に何かルールが1つでもあるか(`hasAnyRules`)で判定を統一した。属性ごとに判定を分けても体験差が薄く、実装も煩雑になるため
- D-2で `.ladder-thumb.is-target` を朱塗りにしたことに伴い、動きの強さ(intensity)メーターの「埋まっているバー」(`--vermilion`)が背景と同化して見えなくなる副作用があった。`is-target` の中だけ埋まっているバーを `--ink` にする例外を追加して解消した

## HTMLページ取り込み(PLAN-HTML.md フェーズA〜E)

- `test/domPick.test.ts` は実DOM上でのCSSセレクタの一意性判定(`querySelectorAll`)を検証する必要があり、
  jsdomなしでは書けない。PLAN-HTML.mdの「新しい依存パッケージは追加しない」はREADMEの非目標(アプリ本体を
  軽量に保つ)が主眼と判断し、devDependencyの`jsdom`のみ追加した(アプリのビルド成果物には含まれない)
- ブックマークレットは、ビルド時最小化スクリプトを新設する代わりに、`public/bookmarklet.js`(可読なJS)を
  Viteの`?raw`インポート(標準機能。新規依存なし)で`src/bookmarklet.ts`に読み込み、`javascript:`を
  前置して使う方式にした。手打ちでエスケープした文字列定数より、実ファイルの方が壊れる余地がない
- `HtmlBoard`の`#uic-preview`(こうしたいCSS)は、`</head>`の直前に挿入する。`<head>`の直後に置くと、
  元ページの同じ詳細度のルール(例: `.hero h1`と`h1:nth-child(1)`はどちらも詳細度(0,1,1))に
  カスケードの「後勝ち」で負けて反映されない。実機で発見し、挿入位置を`</head>`直前に修正した
- HTMLページの高さ実測は、iframeの高さを一時的に`0px`に潰してから`scrollHeight`を読む。
  `documentElement.scrollHeight`はiframe自身の表示高さを下限として返すため、潰さずに測ると
  常に前回設定した高さ(初回は既定の800px)以上の値しか得られず、中身が短いページで縮まらない
- 色ノートの追加時、`spot.element`があれば`element.computed.color`を`current`の初期値にする
  (計画の出力例「#E4572E → #C94A1D(落ち着かせる)」は方向チップ由来で、方向チップは`current`が
  ないと押せないため)。ただし`ColorPicker`の「今の色」表示欄自体は`hasImage`(画像ページ向け)で
  出し分けており、HTMLページでは表示されない。方向チップは使えるが値の確認ができない、という
  小さな見た目の粗さが残る。スポイトに相当する「今の色」欄をHTML要素向けに新設するのは計画の
  明示要求を超えるため見送った
- `Board.tsx`は計画で「触らない」指定のため、Escape/Delete/Backspace/Ctrl+Zのキー操作は`HtmlBoard.tsx`
  側に同じ内容を再実装した(共有フックへの切り出しはBoard.tsxの変更を伴うため避けた)。矢印キーでの
  移動は`spot.element`があると`getSpotEditTarget().apply`が何もしないため、あえて実装していない
- `uniqueSelector`は id → タグ+単独class → 祖先を辿った合成(最大5階層、`:nth-child`混じり)→
  全階層`:nth-child`の完全パス、の順に一意になった時点で確定する。5階層以内で一意にならない
  巨大なDOMツリーでは、可読性より確実性を優先して完全パスにフォールバックする
- `readComputed`は`margin`/`padding`/`border-radius`/`border-width`について、ブラウザの
  shorthand computed値(4辺まとめ)ではなく、それぞれtop相当の1辺(`marginTop`等)だけを読む。
  ラダーが単一の数値段階(px)を前提にしているため、4辺が異なる場合でも代表値1つに単純化した

## 破 H3(指示書)

- `boardToLines`への切り替えは、内部の各生成関数(`formatNote`・`positionLines`・`spotSection`等)を
  文字列連結からLine配列組み立てに書き換える形で行った。`boardToMarkdown`は`boardToLines(...).map(l
  => l.text).join('\n')`にしただけで、金型テストの出力は1文字も変えていない
- Paletteのポップオーバーはネイティブ`popover`属性を使った。`.board-surface`が`overflow: hidden`を
  持つため、通常の`position: absolute`な子要素だとポップオーバーが箇所の近くでクリップされる
  (実機で確認)。popoverは表示だけ最上層(top layer)に escape するため、位置計算はJSで
  (`getBoundingClientRect`から)行うが、DOM上の親子関係は保たれるので`closest('.palette')`によるイベント
  判定はそのまま使える
- `Board.tsx`の`onSurfacePointerDown`が「箇所作成のドラッグ開始」を`.spot-rect, .edit-box`以外の
  クリックすべてに対して行っていたため、パレットのボタンを押すと(バブリングで)クリック扱いになり
  選択解除されるバグを実機で発見した。ガードに`.palette`を追加して修正した
  (同種の問題が`LensToggle`にも当てはまるはずだが、レンズ切替は解除されても実害がないため据え置いた)
- H3の指示書(Sheet)は`boardToLines`が返す行をspotIdでグループ化してカード化する。ページ見出し
  (`## p.N`、spotIdなし)は現時点では画面に出していない(エクスポートの文言には引き続き出る)。
  複数ページのボードでSheetにもページ区切りを出すのは今回のスコープ外とした
  (`ponytail:` 将来必要になれば`pageId`でも束ねられるよう、Lineに`pageId`は残してある)
- 引き出し線(`LeaderLine.tsx`)はスクロール追従のため`requestAnimationFrame`で毎フレーム再計算する。
  同時に1本しか引かないため負荷は無視できると判断した
- パレットバーの縦位置(`px.y - 40`)は、箇所がボード上端に近いと画面外にはみ出すことがある
  (実機で確認)。ポップオーバー自体はpopover属性で最上層に出るため機能はするが、バーとキャプション
  の表示位置がボードの外に出て見えないことがある。ビューポート端でのクランプは今回は行っていない
  (`ponytail:` 箇所が上端付近のときにバー位置を反転させる、が次の一手)
- S8の「透明・0px・既定値は出さない」を満たすため、`rgbStringToHex`がalpha=0のrgba()に対してnullを
  返すよう修正した(alphaを捨てたhexだと「不透明な黒」と区別が付かず、実機で背景色が誤って
  「#000000」と表示される不具合を発見した)。この修正は`readComputed`経由で色ノートの初期値seedにも
  影響するが、透明を透明のまま扱うほうが正しい挙動なので許容した
- ColorPickerの「今の色」欄は、S8の指示どおり`hasImage`ではなく`current`の有無で出し分けるよう
  修正した。HTMLページの箇所でも実測した文字色があれば「今の色」が見えるようになる
  (ただしスポイトボタンは画像ページのみ引き続き表示。HTMLページには「拾う」対象の画像がないため)

## 破 H4・H5・H6

- H4のボード上端トグルは、LensToggleと同じ`.lens-toggle`見た目を再利用し、左右反転(`.image-role-
  toggle`)で対称に置いた。HTMLページには出さない(HTMLは取り込み時に常にdraft固定のため意味がない)
- H5の画像コピーは、複数の画像ページがあっても最初の1枚(番号付き画像)のみをクリップボードに
  入れる。クリップボードAPIは1回の書き込みで1画像が実用的な上限のため、複数ページ分をまとめて
  渡す手段は今回作らなかった(必要ならR3の校正紙1枚に統合する方向で解決するのが筋が良さそう)
- H5の「書き出し」ドロワー(旧ExportDrawer)は、JSON書き出しと画像の個別保存のためだけに残した。
  主動線のコピーはSheet最下部の「AIに渡す」に一本化した
- H6の入口小窓は、Ghost.tsxをそのまま流用して1280x1600のサンプルを幅280pxに縮小し、上半分だけ
  `overflow: hidden`で見せている。操作は`pointer-events: none`を内側の要素全部に掛けて無効化し、
  外側の`<button>`だけがクリックを受け取る
- 入口ロゴのインラインSVG化(H6「余力があれば」)は見送った。驚きの演出としての優先度が低く、
  他の項目(R1〜R4)を優先する判断

## 離 R1(測る・色の棚卸し・ばらつき診断)

- R1-aの「測る」ボタンは、既存のラダーノート(段をすでに選んだ状態)にのみ表示する。新規追加中の
  ラダー(まだノートがない状態)には出さない。測定結果はcurrentにのみ書き込み、target(こうしたい)
  は変えないため、「まず段を選んでから測る」という順序を強制しても実害が小さいと判断した
- 定規の長さ→1280基準pxの換算は、画像の実ピクセル幅を経由せず「表示pxの比率(dragPx÷cr.width)×
  1280」で直接求めている。比率で表しているため実ピクセル幅は数式上打ち消し合い、結果は同じになる
- 定規・スポイトと同じ理由で、測定モード中でも既存の箇所(spot-rect)の上をドラッグすると箇所の
  選択が優先され、測定にならない(`onSurfacePointerDown`の`.spot-rect`除外ガードが先に効くため)。
  スポイトも同じ制約を元々持っていたため、今回は揃える形で許容し、直さなかった
- R1-cの「ルールで校正する」で複数の箇所を一括作成する際、`nextSpotNumber(board)`を毎回呼ぶと
  `board`(useEffectのクロージャ)が更新されないため全部同じ番号になるバグを実機で発見した。
  `updateBoard`のrecipe内でローカルに採番するよう修正した(1件だけ作る通常のクリック採取では
  問題が起きないため、複数一括作成のときだけ顕在化した)
- R1-cのルール逸脱判定は、`rules.type`(文字サイズ)と`rules.palette`(色)のみを比較対象にした。
  役割は「本文/文字」があればそれを優先し、なければ先頭のルールを使う簡易ヒューリスティックにした
  (複数ロールのルールがあるとき、要素がどの役割に対応するかを厳密に判定する仕組みは作っていない)
