# 実装中の判断ログ

- アプリ名を計画時の「Sashi」から「UI ColLabo」に変更(ユーザー指定)。package.json name は `ui-collabo`、schema id は `ui-collabo/1`。4.1〜4.3のダジャレ(指し/差し)・ロゴ意匠は名前に依存するため、ブランド資産(brand/一式)はPhase4で改めて設計する
- 白紙ページのアスペクト比は Web=1280×1600、スライド16:9=1280×720、4:3=1280×960 の仮の寸法とした(実データには保存せず、表示比率の計算にのみ使用)
- 「点線箱をドラッグして他の箇所の辺・中央線に4px吸着」のうち、ボード中央線への吸着のみPhase1で実装。他の箇所の辺への吸着とガイド線表示はPhase2以降に見送り
- 右パネルの位置チップは 上/下/左/右(2%)と左右・上下中央のみPhase1で実装。「他の箇所と端をそろえる」チップはPhase2以降に見送り
- リサイズハンドルは反対側の辺を超えて反転させる操作は未対応(幅・高さ0で止まる)
- トップバーの「ルール」「ライブラリ」ボタンはPhase3で該当ドロワーを実装するまで表示しない
- favicon.svg は最小の仮アイコン(ink四角+vermilion点線四角)を先行配置。manifest.webmanifest とその他 public/ 資産(icon-512.png、og.png)はPhase4で追加
- 白紙ボード(imageRole===null)の指示文は「## レイアウト」節に「箇所: ゾーン(x/y/w/h%)」の形で出力し、ゾーンは3x3の粗い判定(左上/右/中央など)で決めた(仕様5.8の例に準拠)
- 画面構成図(5.2)にはボード一覧へ戻る導線が明記されていなかったため、トップバーの「UI ColLabo」ワードマークをクリックすると一覧(Empty画面)に戻る仕様を追加した
- 複数ページを持つボードの指示文出力は、現状ページをまたいで箇所を1つの「## 箇所ごと」にまとめて出力する(ページ単位の見出し分けは未実装)。ヘッダーの「画像サイズ」も pages[0] のみを見る。仕様にマルチページの出力フォーマット規定がないため、単一ページ運用を前提としたPhase1の暫定挙動とし、Phase2以降で必要になれば見直す

## Phase 2(見て選ぶ)

- ラダーの相対チップは5.6.1の語彙(ずっと小さく/少し小さく/少し大きく/ずっと大きく)をそのまま出力に使う。5.8の例文にあった「今より1段小さく」という言い回しは、5.6.1のチップ仕様が確定する前の初期メモと判断し採用しなかった(Phase2受け入れ基準の文言「文字を少し小さく」が5.6.1側の語彙と一致することからも裏付け)
- 「＋ こうしたい」の分類は5.4の「位置・大きさ/色/文字/余白/形/動き/ルールに合わせる/ひとこと」を字義通りには分けず、実装上は「色/文字の雰囲気/量(ラダー、8属性から選択)/動き/ルールに合わせる/ひとこと」の6分類にまとめた。余白・形(角丸・線の太さ)・全体の大きさはいずれもラダー8属性の一部であり、量として一箇所にまとめる方が「選択肢は実物で見せる」原則にも合うと判断
- 色ノートは1箇所に複数付けられる(役割違い、例: 文字色と背景色を両方指定)。文字の雰囲気・動きは1箇所につき1つのみ(仕様の想定に合わせる)
- 動きのプレビューはクリック/ホバーで再生されるが、強さ(intensity)は視覚的な差までは作り込まず、出力テキストにのみ反映する(ponytail: 5段階の見た目差の作り込みは省略、必要になれば強度に応じた移動量・不透明度の変化を追加)
- 「ルールに合わせる」は `docs/DECISIONS.md` の`ruleRefOptions`が返す項目がある場合のみ表示する。Phase3で「ルールにする」ボタンが実装されるまでは常に非表示になる想定
- 参考画像(imageRole=reference)モードの色ノートは、スポイトで拾った値をそのまま target に入れ、出力は「参考画像①の色 #hex を強調色に」の形にする(仕様5.8の例文どおり。role未指定時は「強調」を既定にした)
- 位置・大きさの差分(targetRectとrectの比較)は imageRole==='draft' のときだけ出力する。draftで箇所を作ったあとにimageRoleをreferenceへ切り替えても、古いtargetRectの差分が紛れ込まないようにするため

## Phase 3(蓄積)

- 色ノートの役割(5.6.2: 文字/背景/強調/線)とルールのパレット役割(6章のスキーマ: bg/text/accent/sub)は仕様上も語彙が異なる。「ルールにする」で昇格するとき、線(line)は最も近い補助(sub)に対応させた
- 「ルールにする」ボタンは、Rulesの型(palette/type.mood/type.size/spacing/motion)に対応が付けられるノート(色/文字の雰囲気/ラダーのfontSizeとspacing/動き)にのみ表示する。weight/radius/scale/lineWidth/intensityのラダーはRulesに対応する項目がなく、ボタンを出さない
- 文字の雰囲気・文字サイズをルールへ昇格するときは、見出し/本文/注釈のどの役割かをその場で選ばせる(3つのボタン)。箇所のノート自体には役割の概念がないため
- rules.spacing は段階のステップ番号(LADDER_TABLE.spacingのインデックス)として保持する(pxそのものではない)。出力・ライブラリ表示時は`LADDER_TABLE.spacing.steps[spacing]`で実値に変換する
- 型(テンプレート)は画像を捨てて箇所とルールを複製したボードとして保存し、「型から新規」は型のページ構成をそのまま維持して(白紙のまま)id を振り直して開く。テンプレート自体もimageRole=nullに固定する(画像がないため)
- サンプル2件(Webページ・スライド)は `src/samples.ts` にSVGの模擬スクリーンショットとして埋め込んだ。Phase4で `public/samples/*.json` へ切り出す想定だが、Phase3時点では「開く」画面から直接複製して開ければ要件を満たすと判断した
- 基準ルールの出力(見出し)は内部id(例: `quiet-mincho`)ではなく日本語ラベル(静かな明朝)に変換して表示するよう、Phase2時点の実装から修正した(色・文字・動きのロール名も同様に日本語化)

## UI改善(PLAN-UI.md フェーズA〜E)

- LivePreview(`src/panels/LivePreview.tsx`)の高さ制限は、PLAN-UI.md 記載の `max-height: 40%` ではなく `40vh` を採用した。`.side-panel` の2段グリッドは行が `auto` サイズのため、子要素へのパーセント指定の基準が定まらず機能しない。ビューポート高基準の `vh` なら常に確定値になり、意図(画面の4割程度に収める)も達成できる
- `.live-preview` に `overflow: hidden` を追加し、`.live-preview-body` に `flex: 1; min-height: 0;` を追加した。付けないと `display:flex` 内の `overflow:auto` 子要素が内容の実サイズまで伸び、ページ全体が縦スクロールしてしまう(flexboxの既知の挙動)。ブラウザ実機確認で発見して修正した
- フェーズB-3の「`.app-shell.is-drag-over` の見せ方を強くする」は、実装上はApp側の `dragOver` ステートを `Empty` へpropとして渡し、`.empty-dropzone.is-drag-over` に直接スタイルを当てる形にした。ドロップ処理自体は既存どおりApp最上位の1箇所に残し、二重登録によるファイル二重取り込みを避けている
- C-3「このボードの基準にする」の`<details>`初期開閉は、対象ノート種別ごとの既存ルール有無ではなく、ボード全体に何かルールが1つでもあるか(`hasAnyRules`)で判定を統一した。属性ごとに判定を分けても体験差が薄く、実装も煩雑になるため
- D-2で `.ladder-thumb.is-target` を朱塗りにしたことに伴い、動きの強さ(intensity)メーターの「埋まっているバー」(`--vermilion`)が背景と同化して見えなくなる副作用があった。`is-target` の中だけ埋まっているバーを `--ink` にする例外を追加して解消した
- `brand/*.svg` をコンポーネントから `import` できるよう `src/vite-env.d.ts`(`/// <reference types="vite/client" />`)を追加した。D-4で計画されていた「`public/` へコピー」ではなく、vite標準のアセットimportを使う方式にした。base(`./`)がGitHub Pagesのサブパス配信のため、`public/` 直下を絶対パス参照するとデプロイ後にパスがずれる懸念があり、vite解決に任せた方が安全と判断した
- C-4(指定一覧をパネル上部にまとめる表示)は計画書側で「余力があれば」の推奨扱いだったため、今回は見送った
- 動作確認用に `.claude/launch.json` を追加した(コード本体ではなく開発ツール設定)。既存の別セッションが同名devサーバーを起動していたため、`autoPort: true` で衝突を避けるようにしている
