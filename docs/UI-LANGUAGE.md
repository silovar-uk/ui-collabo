## 1. 操作の語彙

このアプリに存在する操作の全リストと、各操作が出力(指示文)のどの行になるかの対応表です。

| 操作 | 対象 | 発火条件 | 出力のどの行になるか |
|---|---|---|---|
| 囲う | 画像ページの箇所 | [Board.tsx](../src/board/Board.tsx) の矩形ドラッグ(8px超) | `### {n} {label} (x{}%, y{}%, w{}%, h{}%)` 見出し + 位置チップ操作時の差分行 |
| 指す | HTMLページの箇所 | [domPick.ts](../src/lib/domPick.ts) の `attachPicker` click | `### {n} {label} \`{selector}\`` 見出し + 「要素: `<tag>`「text」」行 |
| 段階から選ぶ | ラダー8属性(fontSize/weight/spacing/radius/scale/lineWidth/speed/intensity) | [Ladder.tsx:79-85](../src/pickers/Ladder.tsx) の絶対段クリック | 「{属性名}: 現在値 → 目標値」行 |
| 相対チップ | 同上 | [Ladder.tsx:65-73](../src/pickers/Ladder.tsx) の `RELATIVE_CHIPS` | 同上(delta解決の結果) |
| 実物カード | 色方向・フォントの雰囲気・動き | [vocab.ts](../src/vocab.ts) の各定数(`COLOR_DIRECTIONS` / `FONT_MOODS` / `MOTIONS`)クリック | 色/文字の雰囲気/動きの各行 |
| トグル: 残す | `Spot.keep` | チェックボックス | 「変えないもの」節への箇所追加 |
| トグル: 役割 | `Note.role` / rule参照 | chip-row | 行末の括弧書き、または「ルールに合わせる」行 |
| トグル: いま/こうしたい | `HtmlBoard.showCurrent` | [HtmlBoard.tsx:133-140](../src/board/HtmlBoard.tsx) | **どの行にも対応しない**(第2節、破れ#9) |

## 2. 状態の語彙

「今」「こうしたい」「変えない」の3状態が、色・線種・位置でどう表現されるかです。

| 状態 | 色 | 線種 | 対応データ |
|---|---|---|---|
| 今 | 墨色(ink) | 実線 / 塗り | `Spot.rect`、`Note.current`、`ElementRef.computed` |
| こうしたい | 朱色(vermilion) | 点線(`targetRect`) / 塗り(`.is-active`) | `Spot.targetRect`、`Note.target` |
| 変えない | 無彩色(チェックボックスのラベルのみ) | なし | `Spot.keep` |

「今」を示すデータソースが3つ(手動 `current` / 実測 `computed` / 画像スポイト)ある一方、視覚表現は統一されていません。詳細は第2節「破れ」を参照してください。

## 3. 物差し

`vocab.ts` の各テーブル(`LADDER_TABLE` / `COLOR_DIRECTIONS` / `FONT_MOODS` / `MOTIONS`)は、
「実物を並べられる離散段階の物差し」です。px値そのものではなく段(index)で保持する理由は次の2点です。

- 相対語彙(「少し」「ずっと」)を `delta` という共有単位で扱えるようにするため([PLAN.md](../PLAN.md) 1章「量が伝わらない」への回答)
- 各段を実物として描画できるようにするため([PLAN.md](../PLAN.md) 10-3「選択肢は実物で見せる」)。連続値では段階的な実物プレビューを用意できません

段のインデックスは属性間で共有可能な整数であり、`Rules.spacing` のような「基準」の保存や、
`resolveLadder` の「最も近い段を探す」計算にそのまま使えます。

## 4. 破ってはいけない線

- 数値入力欄を作らない(色hex以外)
- 名前だけの選択肢(実物を描画しない項目)を作らない
- 出力に現れない操作を新設しない
- 「今」を推定しない。画像ページはユーザーが手動でセットする。HTMLページで自動化する場合は、
  何を根拠に自動化するかを明示的に判断する(第5節「離」参照)

**完了条件の判定**: 既存画面のすべての対話要素は上記1〜3のいずれかに分類できますが、
`html-board-toggle`(いま/こうしたい表示切替)だけは分類できません。「今/こうしたい/変えない」の
どれでもない第4の軸です。分類できない要素として第2節に記録しました。

## 6. 参照実装メモ

「対象の確定」と「量の指定」の2点に絞って3つを見ました。

**Chrome DevTools** — 対象確定はクリック選択+セレクタパスの自動表示 / 量指定はStylesペインへの直接数値タイピング /
「今」の扱いは実測値と編集値が同一フィールドで区別されず、常に「今」を直接書き換える /
違い: このアプリは変更を確定させず「今→こうしたい」の差分を言語化するだけに留める。

**Figmaのコメント** — 対象確定はキャンバス上へのピン留め(点、領域を持たない) / 量指定は自由記述のみで
構造化された物差しがない / 「今」の扱いはコメント時点のフレームに固定され、後のバージョン変更に追随しない /
違い: `Spot` はDOM要素または矩形という「領域」を持つため、量の対象範囲自体が指示文に明示される。

**Framer** — 対象確定はレイヤーツリーのクリック選択 / 量指定はプロパティパネルの数値入力・スライダー /
「今」の扱いは選択と同時に実値がインスペクタに表示され、変更は即座に実データを上書きする /
違い: Framerは値を確定させる責任を持つ実デザインツールだが、このアプリは値を確定させない前段ツール
([PLAN.md](../PLAN.md) 3章の非目標そのもの)。

## 7. 離の候補(採点付き)

軸: A導出性 / B不可逆性 / C出力貢献 / D削減性 / E実物性(各0-3点、合計12点未満は却下)。

```
候補A: 「今」は状態ではなく取得経路の名前である
原理: Note.current(手動申告)とElementRef.computed(自動実測)は同じ「今」概念の2経路であり、
実測できる場面では実測を優先し、手動入力は実測不可時のフォールバックに退く。
減るもの: HTMLページの「今」ボタン(ladder-now)
変わること: ラダーに実測ベースの現在地マーカーが自動表示される
反証: 白紙ボード・参考画像モードなど実測もスポイトもできない場面には適用できず、手動入力の型が残る
採点: A3 B2 C2 D3 E2 = 12

候補B: ラダーは絶対段の選択リストではなく、現在地からの相対移動を主体とする物差しである
原理: すべてのラダー操作を「今の位置」を起点とした移動として扱う。絶対段クリックも
相対チップも、現在地マーカーを軸にした同一の操作として描画する。
減るもの: 絶対選択と相対チップという2方式が「現在地からの移動」1つに統合され、ladder-nowボタンが
実測可能な場面で不要になる
変わること: ラダーが「現在地マーカーを起点に、両側へ動かす」見た目になる
反証: 白紙ボード(今が存在しない)では現在地からの移動が無意味で、絶対値選択に頼るしかない
採点: A3 B2 C2 D3 E3 = 13  ← 採用

候補C: 「指す」は「囲う」の特殊形ではなく、「囲う」が「指す」の特殊形である
原理: すべての箇所作成は「対象を確定する行為」であり、矩形は自由形の指す、要素クリックは
構造に沿った指す、に過ぎない
減るもの: 「囲う操作」「指す操作」という別々の説明文が1つに統合される
変わること: 空状態のヒント文言がページ種別で自動切替(破れ#4が解消)
反証: 画像ページは位置微調整が主要操作であり続けるが、HTMLページでは位置調整の概念自体が消える(3.5)。
1つの原理で説明しきれない
採点: A2 B1 C1 D2 E2 = 8(却下)

候補D: 出力の対象言語は入力ではなく箇所の型が決める
原理: 出力タブを選ばせず、常時「このボードはWebページ向け/画像向けに渡ります」の1行を自動判定表示する
減るもの: ExportDrawerの画像タブ出し分けロジックが1行の宣言に統合される(実質ほぼ何も減らない)
変わること: 出力の先頭に自動判定バッジが付く
反証: 画像ページとHTMLページが同居する混在ボードでは単一の宣言文で説明しきれない
採点: A2 B1 C2 D1 E1 = 7(却下)

候補E: 箇所は矩形ではなく、常に「比較対象」である
原理: Spotの本体はrect/elementではなく「今の値」と「こうしたい値」のペアであり、矩形・セレクタは
描画位置を決めるための付随情報に過ぎない
減るもの: targetRectとelementが統一的に扱える可能性(ただしスキーマ変更が要る)
反証: SCHEMA非破壊の制約と即座に衝突する
採点: A3 B2 C2 D2 E2 = 11(却下)

候補H: いま/こうしたい表示切替は箇所の状態ではなく、ボードの視点(レンズ)の状態である
原理: showCurrentを箇所のkeep/notesと独立した「ボード全体の視点」として明文化し、画像ページにも
同種のレンズ(全箇所の点線箱を一括表示するトグル)として一般化する
減るもの: 画像ページの「選択中のみ点線箱表示」という固定挙動が視点トグルの一種に統合される
変わること: 画像ページにも右上に同等のビュー切替が付く
反証: 画像ページは元画像を書き換えられないため、切り替えても実質的に「点線箱の重ね描画ON/OFF」にしか
ならず、HTMLページの「実際にCSSが変わる」体験と意味がズレる
採点: A3 B2 C1 D2 E3 = 11(僅差で却下)
```

**最高得点は候補B(13点)**。同点なしのため単独採用。

## 8. 採用案と最小形

**採用: 「ラダーは現在地からの相対移動を主体とする物差しである」**

1. **最小の形** — HTMLページ(`spot.element` あり)のラダーで、実測値から算出した現在地を自動表示し、
   「今」ボタンの手動セットを不要にする。触るファイルは3つ:
   - `src/lib/htmlCss.ts` — `nearestStepIndex` と `parseNumber` を `export` にする
   - `src/pickers/Ladder.tsx` — `autoNow?: number` propを追加。渡されたら `ladder-now` ボタン列を隠し、
     該当段に現在地マーカーを付ける
   - `src/panels/SpotPanel.tsx` — `spot.element` があるとき、実測値から `nearestStepIndex` で
     `autoNow` を計算して `Ladder` に渡す
2. **捨てるもの** — HTMLページ文脈での「今」ボタン(`ladder-now`)。実測があるので手動セットが不要になる
3. **データ構造への影響** — `SCHEMA` は `ui-collabo/1` のまま維持できる。`autoNow` は表示専用の
   派生値で、`Note.current` には書き込まない(実測結果を保存すると、要素側のスタイルが変わっても
   追随しなくなるため)
4. **受け入れ基準**
   - HTMLページで見出しをクリックし、ラダーを開くと、ボタンを押す前から実測値に最も近い段へ
     現在地マーカーが自動表示される
   - 「少し小さく」を押すと、その自動現在地から1段小さい値が目標になる
   - 画像ページのラダーは `autoNow` が渡らないため、従来どおり「今」ボタンでの手動セットのままである
     (回帰なし)

実装セッション用プロンプトは [PLAN-LADDER.md](../PLAN-LADDER.md) を参照してください。
